# Dáreje

Flutter-приложение для учёта студенческих достижений. Интерфейс на казахском языке.

## UI/UX

Светлая нейтральная основа, глубокий violet для главного акцента и отдельные
цвета навыков. Переработаны все рабочие экраны, включая аналитику и симулятор.
Главная показывает кольцо общего балла, реальные последние достижения,
локальное место и быстрые переходы к существующим действиям.

Дизайн-система находится в `lib/utils`: `AppColors`, `AppTypography`,
`AppSpacing`, `AppTheme` и `AppMotion`. Общие компоненты в `lib/widgets`:
`app_widgets.dart`, `achievement_tile.dart` и `dareje_navigation.dart`.
Используются встроенные Flutter-анимации; дополнительные библиотеки не нужны.

Переходы используют fade + slide, карточки реагируют на нажатие,
кольцо и шкалы плавно обновляются. Аватар из рейтинга связан с профилем
через Hero. Длинные описания и пояснения доступны в раскрываемых блоках.
Загрузка отображается skeleton без бесконечного декоративного shimmer.
Системные `disableAnimations` и `accessibleNavigation` отключают эффекты.
При крупном тексте нижняя навигация показывает иконки с доступными подписями.

Категории подписаны на казахском, их значения в хранилище сохранены.
Фильтры достижений не записывают данные. Симуляция по-прежнему не создаёт
достижения и историю. Показатели, рейтинг и графики используют прежние сервисы.

`test/ui_redesign_test.dart` дополнительно проверяет пять вкладок при 320 px
и масштабе текста 2×, уменьшение анимаций, доступность формы при клавиатуре,
раскрытие полного описания, фильтры и обновление кольца без перезапуска.

Сейчас доступны локальная регистрация и вход по логину или почте. Регистрация
запрашивает логин, имя, фамилию, почту, пароль и его повтор. Логин допускает
латинские буквы, цифры и дефис. Пароль содержит минимум 8 символов с буквами
или цифрами; дополнительные специальные символы допустимы.
После регистрации пользователь сразу входит в приложение. Сессия восстанавливается
при следующем запуске, пока пользователь не нажмёт «Шығу».

Аккаунты сохраняются через `shared_preferences`, пароли — в виде PBKDF2-HMAC-SHA256
хешей с отдельной случайной солью. Это учебная локальная логика: аккаунты не
синхронизируются между устройствами, а локальное хранилище не является защитой
серверных данных. Серверная авторизация и Firebase остаются отдельным этапом.

Вкладка «Жетістіктер» показывает достижения текущего аккаунта. Кнопка
«Жетістік қосу» открывает форму: название, описание, категория (Academic,
Programming, Projects, Sport, Volunteering, Other) и дата получения в формате
`ДД.ММ.ГГГГ`. Все поля обязательны. После «Сақтау» новая карточка появляется первой.
Достижения хранятся как JSON в том же `shared_preferences`, отдельно по логину
в ключе `dareje.achievements.v2.<login>` вместе с историей изменений.
Старый ключ `dareje.achievements.v1.<login>` читается автоматически, пока не
сохранена первая новая запись. Перезапуск и выход из аккаунта не удаляют
записи; синхронизации между устройствами нет. Очистка данных приложения или сайта
удаляет локальные достижения вместе с аккаунтами.

Профиль и главная показывают один общий балл — округлённое среднее шести
показателей. `AchievementScoringService` заново рассчитывает их при загрузке
и после сохранения достижения: базовые значения 60, 68, 55, 41, 35, 30 плюс
сумма влияний сохранённых записей. Итог каждого показателя ограничен 0–100;
начисленные баллы отдельно не сохраняются, поэтому повторный запуск их не удваивает.

| Категория | Влияние на показатели |
| --- | --- |
| Academic | Academic +10, Teamwork +2 |
| Programming | Programming +10, Projects +4 |
| Projects | Projects +10, Programming +4, Teamwork +3 |
| Sport | Sport +10, Teamwork +3 |
| Volunteering | Volunteering +10, Teamwork +5 |
| Other | Teamwork +2 |

Вкладка «Рейтинг» показывает **локальный рейтинг** настоящих аккаунтов,
зарегистрированных на текущем устройстве или в текущем браузере. Общего источника
студентов между устройствами нет, поэтому это не глобальный рейтинг университета.
Вымышленные аккаунты не добавляются. Если аккаунт один, экран честно сообщает об
отсутствии других студентов; при пустом источнике показывает empty state.

`LocalRankingDataSource` читает список аккаунтов из `LocalAuthService` через
неизменяемый `registeredUsers` и достижения каждого логина через существующий
`LocalAchievementService`. Профили рассчитываются только существующим
`AchievementScoringService` от базы. `StudentRankingService` сортирует готовые
`StudentProfile.totalScore` по убыванию, при равенстве — по логину. Равные баллы
дают одинаковое место с пропуском следующих позиций: `#1, #1, #3`. Рейтинг не
сохраняет и не начисляет баллы, повторная загрузка не меняет данные.

TOP-3 выделяет всех студентов на местах 1–3, в том числе делящих место.
Текущий аккаунт выделен в списке, его позиция и балл вынесены в отдельную карточку.
Аватары показывают инициалы, поскольку фото в профилях пока нет. Нажатие на
карточку открывает существующий профиль с показателями, если они доступны.
После сохранения достижения рейтинг обновляется при открытии вкладки; доступны
кнопка обновления и pull-to-refresh. Loading и ошибки чтения обрабатываются
отдельно. Ошибка любого профиля блокирует весь результат, чтобы неполный список
не показывал ложные места. Новый backend и зависимости не добавлены.

Вкладка «Талдау» открывает **аналитику личного прогресса**: общий балл,
количество достижений, действительное место в локальном рейтинге, зарегистрированное
изменение за период и наиболее высокие показатели. Интерактивная radar-диаграмма
показывает шесть существующих показателей; категория выбирается касанием оси или
кнопкой в легенде. Line chart поддерживает последние 7, 30, 90 дней и всё время.
Касание / горизонтальное перемещение по графику и кнопки предыдущей / следующей
записи показывают точное время и переход между прежним и новым общим баллом.
Одна запись отображается отдельной точкой. Фильтры считают последние N × 24 часа
включительно; записи с временем в будущем исключаются.

Карточки категорий показывают значение из 100, progress bar, число прямых
достижений и зарегистрированный прирост за выбранный период. При равных значениях
перечисляются все самые сильные / самые низкие показатели. «Даму мүмкіндігі»
означает наименьшее **текущее значение**, а не наименьший темп роста. Teamwork
получает влияние от других категорий и не является прямой категорией достижений;
Other имеет счётчик достижений, но не отдельный показатель.

Хронология сортируется по дате получения от новых к старым и показывает все
достижения независимо от фильтра графика. Для новых записей отображается фактическая
разница показателей и общего балла; для старых — отсутствие сохранённой информации
о влиянии. Дата получения и время сохранения события показаны отдельно.

Архитектура и сохранение истории:

- `ProgressAnalyticsScreen` и `analytics_charts.dart` отвечают за UI, фильтры,
  взаимодействие с графиками, loading / empty / error, обновление и адаптацию.
- `LocalAnalyticsDataSource` читает согласованный `AchievementSnapshot` из
  существующего `LocalAchievementService`, рассчитывает профиль существующим
  Scoring и получает место через прежние источники и сервис рейтинга. При ошибке
  рейтинга место недоступно; неполный список не используется для расчёта позиции.
- `ProgressAnalyticsService` агрегирует готовые значения, фильтрует события,
  считает изменения / количество, определяет крайние показатели и связывает
  хронологию с историей. Новую систему начисления баллов он не содержит.
- `ProgressHistoryService` сравнивает показатели до и после добавления через тот
  же `AchievementScoringService.calculateIndicators`. Общий балл считается только
  `StudentProfile.scoreFor`. Событие содержит ID, UTC timestamp сохранения,
  предыдущий / новый общий балл, фактические разницы шести показателей и ID достижения.
- Достижения и история сохраняются **одним JSON-документом** версии 2 по логину.
  Ошибка записи не оставляет отдельно сохранённое достижение или событие.
  Форма сохраняет случайный ID между попытками; повторное добавление того же ID
  ничего не записывает. Очередь на аккаунт предотвращает потерю параллельных
  добавлений между экземплярами сервиса внутри одного приложения. ID событий
  дополнительно дедуплицируются при агрегации. Расчёт баллов остаётся от базы,
  а не от накопленной истории. События с нулевой разницей также сохраняются.

**Ограничения истории:** до этапа 6 сохранялись только даты получения достижений,
не даты изменения показателей. Прошлые события не генерируются. График пуст,
пока не сохранено новое достижение. Изменение за период показывает сумму только
зарегистрированных событий и может не охватывать весь прошлый период. История
локальна, сохраняется после выхода и перезапуска, но удаляется при очистке данных
приложения / сайта. Между отдельными браузерными вкладками / процессами нет
блокировки записей и синхронизации. Тёмной темы в приложении пока нет; новый
экран использует текущую ColorScheme и совместим с тёмной схемой без смены остальных экранов.

Этап 7 — **Impact Simulator**: кнопка «Ықпал симуляторы» на главной открывает
инструмент прогноза. Выберите одну из шести категорий, затем сценарий и нажмите
«Ықпалды есептеу». Доступны 12 сценариев, включая олимпиаду, хакатон, IT-проект,
спортивную победу и волонтёрскую деятельность. Внутри одной категории тип
сценария не меняет бонусы: применяются только существующие правила Scoring.

Результат показывает «Қазір / Болжам», анимированное изменение общего балла,
каждого показателя и фактический прирост. Radar-диаграмма одновременно показывает
два профиля; касание оси или выбор дағды в легенде выводит точное сравнение.
Переключатель состояний анимирует progress bars, а секция «Балл неліктен өзгерді?»
объясняет влияние на все шесть дағдылар. При достижении 100 показан потенциальный
бонус и меньший фактический прирост; округление общего балла также объясняется.
Повторный сценарий и обновление читают реальные данные заново.

Архитектура симулятора:

- `ImpactScenario` содержит только описания и категорию, без собственной оценки.
- `LocalImpactSimulationDataSource` читает существующие достижения и полный
  локальный рейтинг перед каждым расчётом. Повреждение собственного профиля
  отображается как ошибка; сбой рейтинга оставляет доступными личные показатели.
- `ImpactSimulationService.simulate` принимает реальный `StudentProfile`, сценарий
  и необязательный список реальных профилей. `AchievementScoringService` применяет
  бонусы через общий метод ограничения 0–100. Сервис не создаёт `Achievement`,
  не обращается к хранилищу, времени или генератору ID.
- `SimulationResult` хранит два неизменяемых профиля, реальные разницы показателей,
  потенциальные бонусы, объяснения, общий балл до / после и доступные места.
- Для прогноза рейтинга в копии списка заменяется только свой профиль. Два вызова
  прежнего `StudentRankingService.rank` определяют место до / после; правила ничьих
  `#1, #1, #3` и стабильная сортировка по логину сохранены. Прочие аккаунты и список
  источника не меняются.

**Ограничения:** рейтинг остаётся локальным, без межустройственной синхронизации.
Пустой / недоступный список, повторяющиеся логины и отсутствие своего аккаунта
отображаются без выдуманной позиции. При одном аккаунте показано `#1 → #1` и
отсутствие соперников. Это прогноз одного достижения при неизменных баллах
остальных студентов, а не гарантированное будущее место. Симулятор не добавляет
достижения, не меняет их счётчик, настоящие показатели или историю прогресса.

Для локального веб-запуска используйте постоянный адрес и порт:

```sh
flutter pub get
flutter run -d chrome --web-hostname localhost --web-port 7357
```

Браузер сохраняет вход для конкретного адреса, порта и профиля. На будущем
развёрнутом сайте сохранение будет работать в том же браузере на том же домене.
Смена домена, порта или браузера, приватный режим и очистка данных сайта требуют
новой регистрации: переноса локальных аккаунтов пока нет.

Проверки:

```sh
flutter analyze
flutter test
flutter build web
```

В текущем Windows SDK при кириллице в пути проекта `flutter analyze` может
завершаться внутренней ошибкой LSP, а `flutter build web` — пропускать копирование
статических ресурсов, даже возвращая код 0. Для проверки использован временный
путь к проекту без кириллицы и `flutter build web --output <путь-без-кириллицы>`.
Такая сборка содержит FontManifest и шрифт иконок; ресурсы проверены в браузере.

## APK для Android

Сборка версии для установки на телефон:

```sh
flutter pub get
flutter build apk --release
```

Файл: `build/app/outputs/flutter-apk/app-release.apk`. Универсальный APK содержит
ARM32, ARM64 и x86_64; минимальная версия — Android 7.0 (API 24).
Приложение на телефоне называется **Dáreje** и работает без запущенного компьютера.
Аккаунты, достижения и история сохраняются на телефоне; данные браузера туда
автоматически не переносятся.

Для локальной установки используется существующая debug-подпись release-сборки.
Ключ для публикации в магазине пока не настроен. APK и локальные ключи подписи
не добавляются в Git.
